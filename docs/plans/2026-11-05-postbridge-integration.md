# PostBridge 单向接入与验收

CMS 已实现来源接入、准备稿、分发及取消。跨系统联调、真实 CSDN 草稿及生产验收待完成。任务与验收入口见 [当前任务清单](current-tasks.md)，整体状态见 [主进度](../progress.md)。

## 范围与职责

首期由 CMS 管理员选择一篇已发布文章和一个 CSDN 账号，生成文字 Markdown 准备稿，在 PostBridge 确认平台稿，再回到 CMS 提交、查看结果或取消。分发动作是保存到 CSDN 草稿箱，CMS 发布状态独立维护。

CMS 后端主动调用 PostBridge，负责校验来源、冻结快照、签发限时分发授权、持久化分发记录和可靠发送来源事件。PostBridge 负责管理平台账号、确认平台稿、执行保存和核对外站结果，并依据本地快照、当前应用权限、授权到期时间及已收到的来源事件判断是否继续。CMS 后端查询分发状态，页面读取 CMS 保存的结果。

外部契约以 PostBridge 仓库的 `docs/external-integration.md` 和 `contracts/cms.openapi.yaml` 为准，签名与指纹对照 `tests/fixtures/integration-contract.json`。连接与分发接口见 [PostBridge 接入 API](../apis/postbridge.md)。

## 接入与分发流程

1. PostBridge 管理员签发邀请，CMS 后端注册，PostBridge 审批后通过安全渠道交付凭据，CMS 使用新密钥签名激活并查询授权目标。接入管理和分发操作单独校验 CMS 管理员权限，凭据仅由后端使用。测试与生产独立注册和授权。
2. 后端使用固定 HMAC-SHA256 签名，覆盖实际请求方法、完整目标 URI、原始正文摘要及身份头。正文序列化一次，重试复用冻结正文及业务标识，每次更新签名时间和 nonce。验证空正文、查询编码、密钥轮换及代理转发后的签名。
3. 通过目标查询选择获批的 CSDN 账号，校验已发布文章的预期修订号和内容兼容性。正文仅支持文字 Markdown，拒绝图片、HTML、MDX 组件、代码围栏外的表达式及模块语句。封面和资源按当前契约为空，带封面的来源须由管理员明确选择发送文字快照，保留原文。指纹及标题、正文、摘要、标签和请求大小限制按外部契约验证。
4. 以稳定文章 ID 关联来源版本、单调递增的 `state_seq`、24 小时授权、内容指纹及目标。为准备和提交分别持久化稳定 `request_id` 与冻结正文，再发送请求。保存准备稿 ID 和有效期，预览和详情链接仅接受已配置的 PostBridge origin。
5. 管理员在 PostBridge 确认后，CMS 重新查询准备稿。提交前复核文章状态、来源版本、状态序列、授权、目标和期限，原样提交平台稿修订 ID 与确认指纹。平台稿重编、来源变更或授权失效时要求重新确认适用的准备稿。
6. 提交被接受后保存父分发 ID。超时或响应丢失时，先按原提交 `request_id` 查询。暂未查到且当前授权仍有效时，按原请求 ID 和正文重试。状态查询由 CMS 后端限频执行，遵守 `Retry-After`，持久化父子状态、平台结果和最近核对时间。以子任务的 `draft_saved` 显示「草稿已保存」，将 `unknown` 交由管理员核对。

## 事务发件箱

文章变更或授权撤销、对应的分发状态更新及待投递事件须在同一 PostgreSQL 事务中提交，失败一并回滚。覆盖后台编辑、修订恢复、发布、下架、转私密、导入更新及实际存在的其它写入入口。保留文章修订触发器，独立维护分发状态序列。对存量文章按需初始化分发状态，授权由管理员明确发起。

| 来源变化 | 事件规则 |
| --- | --- |
| 发布或更新 | 发布且已有有效分发授权时发送 `published`。兼容内容更新发送 `updated` 并携带当前授权状态。事件使用对应版本、状态序列和内容指纹，普通发布不自动授予外部分发权限。内容变为不兼容时，撤销受影响的旧授权，不发送私有正文或伪造指纹。 |
| 下架、转私密 | 分别发送 `unpublished`、`private`，使该文章的旧授权失效。 |
| 删除 | 在实际删除入口接入时发送 `deleted`，保留必要的来源标识与序列。 |
| 撤销单份授权 | 发送 `authorization_revoked`，携带该授权的 `authorization_id`。重新授权生成新 ID。 |

创建准备稿可以直接携带来源声明。事务提交后，后台向 PostBridge 的 `POST /api/integrations/v1/source-events` 投递，按租约领取发件箱记录，支持多实例并发、租约过期接管和重启补发。保留稳定 `event_id` 和原始正文，重试时重新签名。暂时失败按退避策略重试，限流遵守 `Retry-After`，长期失败告警并支持以原事件重投。记录次数、下次投递时间、确认时间和脱敏错误。收到 `received: true` 即确认投递，`applied: false` 可表示重复或旧序列，文章状态不得回退。事件冲突保留待排查记录。单份撤销按授权 ID 处理，迟到的事件仍可撤销指定授权。CMS 等待同篇文章较早的文章级事件处理完毕后，再发送新准备稿。

## 撤销与外站结果

- CMS 提交文章下架、转私密或授权撤销后，立即在本地阻止使用已失效的授权创建或提交分发。已冻结但尚未发送的提交在发送或重试前复核当前状态。
- 已发出的请求可能与本地撤销并发。对已知的在途分发尽快请求取消，提交结果丢失时按原请求 ID 找回后继续处理。来源事件持续投递，取消结果与事件确认分别记录。
- PostBridge 在取消生效、收到并应用相关失效事件、应用失效或快照授权到期时，依据本地记录阻止后续写入。CMS 本地提交与远端生效之间存在窗口。准备稿预览到期限制确认和提交，已接受的任务仍按授权期限和执行守卫判断。
- 对 `409 distribution_not_cancellable`、`unknown` 或正在核对的任务继续查询，并提供 PostBridge 详情入口。已保存的 CSDN 草稿留在外站，结果未知时由管理员核对，禁止换请求 ID 或重新准备来重复写入。

| 撤销边界 | 验证本地立即拒绝旧授权，模拟事件暂不可达时的远端窗口，确认远端接收失效事件或取消生效后阻止可停止任务，并验证授权到期。单份撤销不影响同一文章的其他有效授权。已保存或结果未知的任务不重复写入。 |
| 环境验收 | 在独立环境完成仅由 CMS 主动发起请求的跨系统闭环。经授权后使用真实 CSDN 账号核对草稿及 CMS 回显。生产单独核对 HTTPS、代理、时钟、限流、密钥配置与投递告警；执行 migration 前备份 PostgreSQL。 |
