# Rendering 博客接入 CMS 相册、照片与文章封面

本文可整份交给 Rendering 博客项目会话使用。接口以 CMS 当前源码为准；博客现状来自本机 Rendering 源码的只读核对，不代表生产已部署或已通过联调。核对日期：2026-11-01。

## 对接结论与博客现状

CMS 负责相册、照片、发布状态和图片地址；Rendering 负责页面、分页交互、图片展示和懒加载。博客使用公开接口，无需后台令牌，也不连接数据库或持有对象存储凭据。

| 范围 | 已核实的能力或问题 | 博客应做的工作 |
| --- | --- | --- |
| 相册列表 | CMS 已有服务端分页；博客 components/pages/photos-index-page.tsx 调用 getPublicAllPhotoAlbums，后者在 lib/public-content.js 循环读取各页，每页 100 条 | 页面改用单页查询，首屏只取 12 本相册，翻页或触发加载更多后再取下一页 |
| 相册照片 | CMS 已有服务端分页；博客 components/pages/photo-album-page.tsx 已按页获取照片并显示 PaginationBar | 保留按页查询，补充按需加载下一页的交互；不得改成获取整本相册 |
| 图片下载 | 博客相册球形组件、照片条带等已使用 loading="lazy" | 保留图片懒加载，并验证这些布局中真实的图片请求数量；该属性不能减少相册 JSON 的获取数量 |
| 文章封面 | CMS 列表和详情均返回 coverImageUrl；博客 lib/cms-content.js 当前只读取 coverImage / cover_image，会遗漏 CMS 正式字段 | 优先读取 coverImageUrl，映射为博客内部的 coverImage，供卡片和需要封面的详情展示使用 |
| 空封面 | CMS 允许相册封面三个字段为空；博客 lib/cms-photos.js 当前会过滤无有效封面的相册 | 保留相册文本和数量，使用占位图，不因可选封面为空丢弃相册 |
| 失败状态 | CMS 读取层区分不存在、失败和无效响应；博客 lib/public-content.js 包装函数把失败收敛为空数组或 null | 页面保留可区分的状态，服务故障显示重试，不伪装成没有相册或相册不存在 |

本次交付为对接说明，博客分页增强和字段适配须在 Rendering 仓库实施、测试与部署。

## API 地址与调用边界

博客服务端沿用 CMS_API_BASE，值包含 /api/v1。仓库约定的公开基地址为 https://cms.rendering.me/api/v1，本地示例为 http://127.0.0.1:8080/api/v1；博客会话须核对自身运行环境，不把示例当作已验证的生产配置。

首屏及页面元数据在博客服务端读取。加载更多优先通过博客自己的同源只读路由查询 CMS，只允许固定公开相册路径及经过校验的 slug、page、limit，不接受任意上游 URL。该博客路由需要新增或复用，不是 CMS 已有路由。若浏览器直连 CMS，须核对 CORS 白名单；不要把后台凭据或服务端配置带入浏览器。

下表为完整 CMS 路径；拼接 CMS_API_BASE 时只追加 /photos 或 /articles 等后缀，避免重复 /api/v1。

| 用途 | 方法与路径 | 返回内容 |
| --- | --- | --- |
| 相册列表 | GET /api/v1/photos?page=1&limit=12 | 相册元数据数组及分页信息，不含每本相册的照片数组 |
| 相册详情 | GET /api/v1/photos/{slug} | 单个相册元数据对象，直接返回对象，不包在 data 中 |
| 照片清单 | GET /api/v1/photos/{slug}/photos?page=1&limit=24 | 当前页照片数组及分页信息 |
| 相册浏览上报 | POST /api/v1/photos/{slug}/views | 成功或当日重复访问返回 204，无响应正文 |
| 文章列表与封面 | GET /api/v1/articles | 文章摘要数组，每项含 coverImageUrl，不含 bodyMdx |
| 文章详情与封面 | GET /api/v1/articles/{slug} | 单个文章对象，含 coverImageUrl 和 bodyMdx |

公开相册查询只返回 published；不存在、未发布或非法相册 slug 返回 404。相册 slug 由小写字母、数字及中划线组成，例如 city-nights，对应博客 /photos/city-nights，不套用文章六位短链规则。文章页面链接优先使用 canonicalSlug，对应 /blog/{canonicalSlug}。

## 相册和照片字段

### 相册元数据

列表每一项与相册详情使用相同的公开字段。

| 字段 | 类型 | 博客用途及空值处理 |
| --- | --- | --- |
| slug | string | 相册路由和合并分页数据时的唯一标识 |
| title | string | 中文标题 |
| titleEn | string/null | 英文标题；为空时回退 title |
| description | string | 中文导语 |
| descriptionEn | string/null | 英文导语；为空时回退 description |
| coverUrl | string/null | 绝对公开图片 URL；为空时显示占位图 |
| coverWidth / coverHeight | number/null | 封面像素尺寸；有效时提前保留图片比例 |
| publishedAt | string/null | 发布时间；空值不导致整项或整个列表解析失败 |
| tags | string[] | 展示标签，不纳入文章标签筛选体系 |
| photoCount | number | 相册照片总数，不是本次返回的照片数 |

封面优先采用 CMS 后台指定照片，未指定时采用相册顺序中的第一张；照片删空时 coverUrl、coverWidth、coverHeight 均可能为 null。列表已有封面和数量，不得为了生成卡片再逐个查询详情或照片。

### 照片信息

| 字段 | 类型 | 博客用途及空值处理 |
| --- | --- | --- |
| url | string | 绝对公开图片 URL，直接用于图片元素或灯箱 |
| alt | string | 无障碍描述，图片元素必须保留 |
| caption | string/null | 可选说明，适合灯箱；为空时隐藏说明区 |
| width / height | number | 服务端提取的像素尺寸，用于布局比例和尺寸占位 |
| takenAt | string/null | 可选拍摄时间；有值才格式化展示 |

公开照片不返回 photoId、assetId、对象 key 或 position，也没有独立的公开单张照片详情接口。照片信息来自当前页清单，图片文件通过 url 获取；追加时使用 url 去重，展示顺序遵守接口返回顺序。

相册上传经过 CMS 校验和隐私元数据剥离；不要在博客侧从图片 EXIF 重新提取 GPS 或拍摄时间。相册发布状态只控制查询可见性，已经拿到的公开对象 URL 不因下架变成私有地址。

## 分页与两层懒加载

### 分页响应

相册和照片清单都返回顶层 data、page、limit、total、totalPages，分别为当前页数组、当前页码、实际每页条数、总条数和总页数。相册默认每页 12 条，照片默认每页 24 条，页码默认 1；limit 超过 100 时按 100 处理。

page 或 limit 非整数、小于 1 时返回 400。页码越界返回 200、空 data 及分页信息；总条数为 0 时 totalPages 为 0。相册本身不存在时，详情和照片清单返回 404。

例如：57 本相册、每页 12 本，共 5 页，最后一页 9 本；87 张照片、每页 24 张，共 4 页，最后一页 15 张。这是计算示例，不是生产数据。

### 数据按页加载

1. 相册首页只查询第 1 页、每页 12 本，把该页数据和分页信息传给展示组件。直接访问带 page 参数的页面时只请求指定页。
2. 相册详情读取相册元数据及指定的照片页，默认第 1 页、每页 24 张；元数据本身不包含照片数组。
3. 提供页码或上一页、下一页链接，使刷新、分享、浏览器后退和关闭 JavaScript 后仍可读取指定页。中英文页面遵守相同规则。
4. 提供“加载更多”按钮，并在按钮或末尾哨兵接近可视区域时触发下一页请求。横向条带观察对应横向容器；球形展示只接收当前已加载数据，可分页切换或按需追加，不为保持球形数量预取所有相册。
5. 同一列表同时只允许一个后续页请求；客户端接管时复用服务端已读取的那一页。成功后才推进页码，失败保留内容并允许重试同一页。
6. 相册用 slug、照片用 url 去重，不重新排序；以 CMS 返回的 page 和 totalPages 判断下一页。不要用过滤后的数组长度判断结束。上游原始 data 为空时停止自动追加；若分页信息仍声称后面有数据，保留手动重试，避免循环请求。
7. 切换 slug、语言、页码或卸载时取消失效请求，防止旧响应写入新列表。结束后解除观察并显示“已全部加载”，不让观察器自动连续遍历所有页。

CMS 使用页码和偏移量分页，没有游标或固定快照。浏览期间发布、删除或排序可能改变页边界；去重不能保证没有遗漏，需要最新完整顺序时从第 1 页刷新。

### 图片文件按需下载

分页限制 JSON 元数据数量，图片懒加载限制图片文件的下载时机，两个条件必须同时满足。

- 屏幕外封面和照片使用懒加载及异步解码；按 CMS 宽高保留比例，空封面提供占位比例。
- 首屏主图可按实际需要优先加载，不把所有封面设为高优先级。
- 灯箱打开后才加载当前大图，必要时只预取相邻少量图片，不通过隐藏图片或预加载逻辑下载整本相册。
- loading="lazy" 是浏览器提示；球形、叠放、横向布局须检查网络请求。若全部图片仍处于浏览器预加载范围，应只给接近展示位置的图片设置真实 src，不能仅凭属性存在认定达标。
- CMS 只有图片 url 和尺寸，没有缩略图接口、独立原图字段或图片变体列表。不要编造 thumbnailUrl、originalUrl、srcset 或缩放参数；大图优化另行使用博客已有且经过验证的图片处理能力。

## 文章封面的获取与展示

CMS 正式字段是 coverImageUrl，类型为 string/null。文章列表每项和文章详情均已包含该字段，无需新增封面查询接口，也不应为了卡片封面逐篇请求正文。

博客在 lib/cms-content.js 的解析函数中优先读取 coverImageUrl，再兼容已有 coverImage 等输入，映射为内部 coverImage；核对 lib/public-content.js、卡片和详情是否保留该字段。components/log-list.tsx 当前已使用 coverImage 展示封面。

| 返回情况 | 博客处理 |
| --- | --- |
| 绝对 HTTPS 地址 | 使用返回地址，不拼接 CMS API 地址 |
| 以单个 / 开头的站内路径 | 视为博客自身资源，例如 /images/blog/example/cover.png；分享元数据需要绝对地址时，以博客公开站点地址解析 |
| null、空串或纯空白 | 文章保持有效，使用占位或默认封面 |
| 非支持协议、无效地址或坏图 | 使用默认封面；限制为受支持的 HTTPS 地址或站内路径，开发环境按需支持 HTTP |

CMS 后台保存封面 URL，导入工具也保留站内路径；公开响应不承诺封面尺寸、alt 或自动选首图。文章封面不保证经过相册上传的元数据剥离链路；不要把文章 coverImageUrl 和相册 coverUrl 混用。

卡片封面可使用装饰性空 alt，详情主图可使用文章标题。封面没有宽高时采用稳定比例，不在首屏逐张读取全部封面的尺寸。空摘要、空标签和空封面都不能成为过滤合法已发布文章的条件。

若文章封面用于 Open Graph / Twitter 分享图，使用解析后的绝对地址；没有封面时使用站点默认分享图，不虚构尺寸。如使用图片优化组件，核对实际资源域名配置；本机 next.config.ts 没有远程图片规则，不能认定任意远程地址都可使用。

文章列表目前返回普通数组，没有相册式分页信封；不要假设添加 page、limit 就会生效。本次分页要求针对相册和相册内照片。

## 缓存、错误与统计

- 相册 GET 返回 ETag 和 Cache-Control: public, max-age=60, stale-while-revalidate=300。If-None-Match 命中时返回 304；自行处理时复用对应页缓存，不把空正文读取为 JSON。
- 缓存键区分 slug、page、limit。博客可沿用约 60 秒再验证；额外代理或页面缓存须计入延迟，不承诺下架后严格 60 秒内从所有缓存消失，也不能无限保留旧相册。
- 照片对象地址含随机标识，上传对象写入一年 immutable 缓存；元数据和图片缓存独立，替换图片使用 CMS 返回的新地址。
- 400 表示参数错误，404 表示不存在或未发布，429 按 Retry-After 退避；网络、5xx 和无效响应显示读取失败与重试。后续页失败保留已加载内容，不能清空列表或标记全部加载完成。
- 相册成功展示后调用对应 views 接口，不在服务端抓取、预取、翻页或每张图片加载时重复上报。204 无正文，404 不重试计数；上报失败不阻断阅读。站点统计沿用已有策略，避免重复接入。
